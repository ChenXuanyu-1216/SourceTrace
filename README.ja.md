AI が生成した知識ツリーを、その元になったスライドと照合して監査する Agent Skill です。

AI ツールを使えば、講義スライドから数秒で知識ツリーを作れます。しかし、定義が間違っていたり、関係がでっち上げられていたり、重要な内容が抜けていたりすることがあります。SourceTrace はすべてのノードとエッジを元の画像と照合し、判定ごとに根拠を示します。**なぜ**問題なのか、スライドの**どこ**にあるのか（ページと引用）、**何**に基づくのか（証拠 ID）です。

Claude Code や Codex など、Agent Skills に対応したツールで動作し、中国語または英語のスライドやウェブページのスクリーンショットを扱えます。

## 出力

スライド画像（PNG/JPG）と知識ツリー（JSON）を渡すと、ツリーと同じ場所の `sourcetrace-output/` に 3 つのファイルを書き出します。

| ファイル | 内容 |
|------|---------|
| `report.md` | 監査レポート：概要、問題、出典メモ（折りたたみ）、欠落、構造の問題、確認済みの項目 |
| `audit.json` | 同じ結果の機械可読版：すべてのノードとエッジの判定 |
| `evidence-index.json` | スライドから抽出したすべての内容。各項目に ID、ページ、原文どおりの引用が付きます |

8 ページの中国語スライドで実行したときの指摘 2 件です。レポートは中国語で出力されています。文は短くし、修正案の列は省略しました（[レポート全文](tests/smoke/model-eval-e2e/report.md)）。

| 编号 | 对象 | 类别 | 风险 | 问题 | 证据 |
|---|---|---|---|---|---|
| F-002 | N005 数据集划分比例 | 概念错误 | 高 | 比例数字错误：树中写"8 : 1 : 1"，课件写"7 : 2 : 1"。 | EV-013 第 2 页 "本课程推荐的划分比例：训练集 : 验证集 : 测试集 = 7 : 2 : 1。" |
| F-004 | E010 过拟合 —related-to→ 高偏差 | 关系错误 | 高 | 关系对调：第 4 页图示为"过拟合 → 高方差"，树中却把过拟合连到高偏差。 | EV-020 第 4 页 "Diagram: 过拟合 → 高方差（对训练数据过于敏感）" |

それぞれの問題は 6 つのカテゴリ（概念の誤り、関係の誤り、根拠のない拡張、過度の一般化、検証不可、欠落）のいずれかとリスクレベルに分類され、すべての指摘に修正案が付きます。追加された細部が 1 つあるだけで、それ以外は資料に裏付けられている定義は、誤りとしては扱いません。低リスクの*出典メモ*として、専用の折りたたみセクションに表示されます。

## クイックスタート

1. 唯一の依存パッケージをインストールします。

   ```bash
   pip install jsonschema
   ```

2. `source-trace/` フォルダを、使っているツールの skills フォルダにコピーします。

   | ツール | Skills フォルダ |
   |------|---------------|
   | Claude Code（個人用） | `~/.claude/skills/source-trace/` |
   | Claude Code（1 つのプロジェクト） | `<project>/.claude/skills/source-trace/` |
   | Codex | `~/.codex/skills/source-trace/`（お使いの Codex のバージョンのドキュメントを確認してください） |

3. スライド画像とツリーを渡して、自分の言葉で依頼します。

   > 这是我的课件截图（slides/ 文件夹）和 AI 生成的知识树 tree.json，帮我对照课件检查一下。

   > Check knowledge-tree.json against my lecture slides in images/.

ツリーは [`knowledge-tree.schema.json`](source-trace/schemas/knowledge-tree.schema.json) に従う必要があります（ノードは `id`、`label`、`definition`、`kind`、エッジは `id`、`source`、`target`、`relation`）。別の形式の場合は、スキルが先に変換し、どう対応させたかを伝えます。PPT や PDF のスライドは、先に画像として書き出してください。

## プライバシー

SourceTrace は AI エージェントの中で動くため、エージェントがスライド画像と知識ツリーを読み込みます。これらはエージェントが使う AI モデルに送られ、そのプロバイダーの規約が適用されます。スキル自体のスクリプトはローカルで動作し、どこにもデータを送りません。

- **AI プロバイダーと共有してよいスライドだけを監査してください。** 講義スライドは通常、講師のものなので、許可が必要な場合があります。
- **出力はスライドそのものと同じように扱ってください。** `evidence-index.json` と `report.md` にはスライドの原文どおりの引用が含まれます。
- **他人のスライドや監査結果を、許可なくコミットしたり公開したりしないでください。**

## どの程度うまく動くか

**合成スライド。** 誤りを仕込んだ 2 つのテストセット（英語スライド 4 ページ、中国語スライド 8 ページ）では、通常の AI アシスタントも SourceTrace も、仕込んだ誤りをすべて見つけました。SourceTrace は、通常のモデルにないものを加えます。

- すべての判定の裏にある証拠 ID、ページ、引用
- すべてのノードとエッジに対する判定
- 固定されたカテゴリとリスクレベル
- 機械可読の `audit.json`
- 的外れな「欠落」項目がないこと
- 中国語のテストセットでの 4 回の実行がすべて同じ結果

その分、トークンは約 30% 多く、時間は約 3 倍かかります。

**実際のコンテンツ。** 中国語版ウィキペディアの記事（CC BY-SA 4.0）を使い、知識ツリーは他の AI ツールで生成したので、誤りは本物です。最初の 2 記事のツリーは OpenAI Codex によるもので、プロジェクトのオーナーが各レポートを審査し、審査のたびにルールを改訂しました。

| 実行 | 審査した項目 | 正しい | 一部正しい | 誤り |
|-----|--------------|---------|----------------|-------|
| 机器学习（機械学習）、1 回目（v0.1.0 のルール） | 13 | 6 | 4 | 3 |
| 机器学习（機械学習）、2 回目（第 1 次改訂） | 18 | 14 | 1 | 3 |
| 决策树学习（決定木学習）、1 回目（第 2 次改訂） | 指摘 11 件 + 確認済み 77 項目 | 85 | 1 | 2 |

v0.3.0 の内容（詳細は [CHANGELOG.md](CHANGELOG.md)）：

- **さらに 2 記事**を第 5 次ルール改訂でテストしました。朴素贝叶斯分类器（ナイーブベイズ分類器、ツリーは ChatGPT 製）：2 回の再実行が全 87 項目で正解と一致しました。感知器（パーセプトロン、ツリーは Codex 製）：どちらの実行もツリーにある 2 つの本当の誤りを見つけ、正しい項目を誤りと判定することはありませんでした。ただし、資料そのものにある、短い導出をしないと気づけない問題 4 つを見落としました。この 2 つの正解は、オーナーが承認した AI によるレビューです。朴素贝叶斯分类器の正解は、ツリーを生成したのと同じ会話から得たものです。
- **規模のテスト**（合成スライド 32 ページ、169 項目のツリー）、**劣化させた画像**（スキャン風、写真風、一部を隠した版）、そして **Codex による 2 回の実行**。

第 6 次ルール改訂は、Codex が感知器（パーセプトロン）で 1 回実行しました。項目の判定は変わらず、短い導出が必要な資料の問題 4 つのうち 2 つを見つけました。この改訂に関わっていない記事ではまだテストしていません。また、すべての審査は 1 人が行うか承認したものです。詳細と注意点：[docs/evaluation.md](docs/evaluation.md) と、各テストセットの `RESULTS.md`。

## 仕組み

SourceTrace は 6 つの段階で動きます：資料の取り込み → 証拠の抽出 → 知識の対応付け → 双方向の監査 → 矛盾の検出 → 監査レポート。判断が必要な部分はエージェントが行います：スライドを読み、主張と証拠を対応させ、判定を選びます。確認や計算ができることは、すべて 3 つのスクリプトが行います。

| スクリプト | 段階 | 役割 |
|--------|-------|------|
| `validate_input.py` | 1 | ツリーと画像を確認し、ページに番号を付け、ツリーが連結していないなどの構造の問題を警告します |
| `validate_evidence.py` | 2 | 証拠インデックスを確認します：ID の一意性、ページと出典の一致 |
| `build_report.py` | 6 | エージェントの `audit.json` をツリーと証拠に照らして確認し、概要と指摘 ID を加えて `report.md` を生成します |

判定、カテゴリ、リスク、欠落のルールは [`references/audit-rules.md`](source-trace/references/audit-rules.md) にあります。その背景にある設計判断は [docs/requirements.md](docs/requirements.md) にあります。

スクリプトは自分で実行することもできます。

```bash
python source-trace/scripts/validate_input.py --tree tests/fixtures/ml-basics/knowledge-tree.json --images tests/fixtures/ml-basics/images
python source-trace/scripts/validate_evidence.py --index tests/fixtures/ml-basics/evidence-index.example.json
python source-trace/scripts/build_report.py --tree <tree.json> --index <output>/evidence-index.json --audit <output>/audit.json
```

2 つの検証スクリプトは `--json` を付けると機械可読の出力になります。`validate_input.py` が書き出す画像パスは、出力フォルダ（ツリーと同じ場所の `sourcetrace-output/`、または `--out` で指定したフォルダ）からの相対パスです。3 つのスクリプトはいずれも、成功すると 0、入力が無効なら 1、使い方の誤りなら 2 で終了します。

## 開発

```bash
pip install -r requirements.txt
python -m pytest
```

テストは 119 件で、約 2 秒かかります。3 つのスクリプト（有効な入力、すべてのエラーと警告のコード、出力の再現性、中国語と英語のレポート）を対象とし、保存されたスキルの実行結果が今も正解を満たすかも確認します。スキル自体はエージェントが必要なので実行しません。新しい実行の採点には `tools/compare_runs.py` を使ってください。

```
source-trace/          スキル本体（インストールするのはこのフォルダ）
├── SKILL.md           手順とトリガーの説明
├── schemas/           JSON Schema：知識ツリー、証拠項目、証拠インデックス、監査結果
├── references/        抽出と監査のルール。必要なときに読み込まれます
└── scripts/           上の 3 つのスクリプト
docs/                  要件と評価
tests/fixtures/        テストセット：正解付きの合成スライド、ウィキペディアのスクリーンショット（CC BY-SA）と監査の実行・レビュー
tests/baseline/        比較用の、通常の AI による実行
tests/smoke/           スキルのエンドツーエンド実行
tests/consistency/     スキルの繰り返し実行
tests/test_*.py        pytest のテスト
tools/                 make_fixture_slides.py、compare_runs.py、degrade_images.py
```

## 現状と次のステップ

v0.3.0。[CHANGELOG.md](CHANGELOG.md) を参照してください。

テストデータの方針：SourceTrace のテストには、オープンライセンスの資料、プロジェクトのオーナーが書いた資料、または合成した資料だけを使います。第三者の講義資料や個人データは使いません。

次に行うこと：

1. **第 6 次改訂のための新しい記事：** どのルールにも関わっていない記事。できれば英語か別の分野で、正解はツリーを作ったのとは別のモデルによるもの。
2. **独立した審査：** オーナー以外の審査者、またはエージェントとは別のモデルによる正解。
3. **実際の画像：** オープンライセンスまたはオーナー自作のスライドの写真やスキャン。
4. **タスクモード：** 厳密な出典追跡モードと、資料外の短い説明を明示したうえで認めるレビューモード。
