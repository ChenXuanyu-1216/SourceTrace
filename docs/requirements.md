# SourceTrace requirements (v0.1)

## Problem

AI tools can turn lecture slides into a knowledge tree in seconds, but the result is not trustworthy by default: a definition may be wrong, a relationship may be invented, and important material may be left out. SourceTrace checks an AI-generated knowledge tree against the original slides and explains every problem it finds with traceable evidence.

It must not stop at "this knowledge point might be incorrect". Every finding answers three questions:

1. **Why** is this knowledge point problematic?
2. **Where** is the source material (file, page, snippet)?
3. **What** is the basis for the claim (the evidence IDs it rests on)?

## Inputs

| Input | Format | Notes |
|-------|--------|-------|
| Original slides | `.pptx` | The single source of truth for v0.1. |
| Knowledge tree | JSON, see `source-trace/schemas/knowledge-tree.schema.json` | Generated by another AI tool. Treated as a claim, never as fact. |

## Pipeline

```
Original PPT + AI-generated knowledge tree
  → Evidence extraction      slides → evidence items with unique IDs
  → Bidirectional review     tree ↔ evidence
  → Structural validation    IDs, references and graph shape
  → Report                   report.md (for people) + audit.json (for tools)
```

### Evidence extraction

Each piece of slide content becomes one evidence item (`source-trace/schemas/evidence.schema.json`) with a unique `evidence_id`, so every finding can cite it. Locations only need to be practical for v0.1: page number plus a text snippet. Precise image coordinates are out of scope.

### Reviewable objects

The tree is split into two kinds of objects, reviewed separately:

- **Node:** is the knowledge point itself correct (label and definition)?
- **Edge:** is the relationship between two knowledge points correct?

These are separate because a node can be correct while its relationship to another node is wrong. For example, "Supervised Learning" and "Unsupervised Learning" can both be well defined while `Supervised Learning —includes→ Unsupervised Learning` is false.

### Bidirectional review

*(Working interpretation, finalized on Day 6.)*

- **Tree → source:** is each node and edge supported by evidence? This catches wrong or invented content.
- **Source → tree:** is each important piece of evidence represented in the tree? This catches omissions.

### Structural validation

Checks that JSON Schema alone cannot express (done in `validate_input.py`, Day 3):

- Node and edge IDs are unique.
- Every edge's `source` and `target` refer to an existing node.
- No edge points from a node to itself.
- `schema_version` is supported.

## Outputs

| File | Audience | Content |
|------|----------|---------|
| `report.md` | People | Summary and findings, each with its reason, location and evidence IDs. |
| `audit.json` | Tools and tests | The same findings in machine-readable form. |

## Out of scope for v0.1

- Sources other than `.pptx` (PDF, video, web).
- Precise image or bounding-box coordinates.
- Automatically fixing the tree. SourceTrace reports problems and does not rewrite the tree.

## Open questions

- Which values are allowed for node `kind` and edge `relation`? The schema accepts any string until this is settled.
- Should speaker notes count as evidence, and if so with their own `type`?
